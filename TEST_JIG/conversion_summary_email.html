Converting old AIO units to the new system with an SD card and two jumpers

Status as of 11 Nov 2026: proven end to end on old unit 2114 (KSNDMC TRG), including normal SD updates afterwards

What it achieves

An old field unit (old LPC1768 bootloader V1.1 and old CTRL firmware) ends up exactly like a new factory unit. No MCU-Link, no cable, nothing to solder. From then on it updates itself from its SD card like any new unit.

Chip Before After
CTRL board (LPC845) Old CTRL firmware, no bootloader New CTRL bootloader + CTRL firmware v1.10, identical to a factory flash
Main board (LPC1768) Old jump loader, old SD bootloader, old application New boot stub + new bootloader + production firmware (e.g. v6.9.31), installed and confirmed through the normal update path
Settings Station ID etc. Unchanged: the new firmware reads the station ID where the old firmware kept it

What the conversion program (fw.hex) is

fw.hex is a small, temporary program (about 48 KB) written only for this conversion. It is named fw.hex because that is the one file name the old unit's own SD bootloader looks for. So the old unit loads it by itself, exactly as it would load an old firmware update. It never sends data to a server and is not the station firmware.

Once running, it does five jobs:

Job What it does
1. Checks Checks itself (CRC), the card, the jumpers and the station type before changing anything.
2. Backs up Saves the old firmware of both chips to the card (MIGRATE folder), so nothing is lost.
3. Programs the CTRL chip Carries the new CTRL bootloader and CTRL firmware v1.10 inside itself and writes them into the LPC845 through JP1/JP2, using the chip's built-in ROM loader. It keeps the unit powered while doing so.
4. Converts the main chip Carries the new LPC1768 bootloader and boot stub inside itself and writes them. It reads the production firmware from the card (fw_ksn_trg.hex etc.) and queues it for installation.
5. Hands over Waits for the jumpers to come off, then restarts. The new bootloader installs the production firmware, which then runs the station.

Each job is checked by reading back what was written. If anything fails, the program stops with a message on the LCD and a report on the card (MIGRATE/RESULT.TXT). After the conversion it stays on the unit only as the "previous firmware" copy. Running it again on a converted unit does no harm: stored records are kept.

What you need

  • One microSD card, formatted FAT32 (32 GB or less, not exFAT), holding:
    • fw.hex: the conversion program
    • the production file for the station type: fw_ksn_trg.hex, fw_bihar.hex or fw_ksn_tws.hex
  • Two jumper caps for JP1 and JP2 on the CTRL board

Field steps

1.Unit off. Fit JP1 + JP2. Insert the card.
2.Power on. Wait about 2 minutes, watching the LCD.
3.When the LCD says REMOVE JP1+JP2, remove both caps.
4.The unit restarts and comes up on the production firmware.
5.Keep the card's MIGRATE folder: it holds both chips' old firmware and the report RESULT.TXT.
6.The clock may be wrong until the first successful send to the server (the next slot), and then corrects itself. Until then a firmware update from the menu is refused with SLOT DUE SOON; just wait for one slot to be sent.

What happens inside, in order

A. The old system loads the converter (about 10 seconds, blank LCD)

  1. At power-up the old CTRL switches the main chip on (and keeps it on for up to 32 minutes).
  2. The old SD bootloader finds fw.hex, writes it to the application area, deletes the file and starts it.

B. Checks, before anything is changed (LCD: CONVERTING UNIT)

  1. The converter checks its own CRC (a damaged copy stops with COPY fw.hex AGAIN).
  2. It saves the old main-chip flash to the card.
  3. It reads the station type from the old settings (a TYPE.TXT file on the card can override it); an unknown type stops here.
  4. It checks both jumpers are fitted (if not: FIT JP1 + JP2).

C. Stage M1: the CTRL chip (LCD: CTRL CHIP ...)

  1. Through JP1/JP2 the main chip resets the CTRL chip into its built-in ROM loader.
  2. Within about 22 ms it loads a 52-byte program into the CTRL chip's RAM, which switches the power back on and keeps it on. (On old units the power board cuts the main chip about 58 ms after the CTRL chip stops driving the power lines.)
  3. It reads the whole CTRL chip and saves the old CTRL firmware to the card. If it already has the new CTRL, nothing is written.
  4. It writes a rescue program to the CTRL chip's first sector first, so a power cut from here still powers the unit up and the conversion carries on.
  5. It writes the CTRL bootloader and firmware and reads every sector back.
  6. It writes the real first sector last, then reads the whole chip back and compares.
  7. The CTRL chip restarts on the new CTRL v1.10.

D. Stage M2: the main chip (LCD: MAIN CHIP ...)

  1. Staging: loads the production firmware from the card into the spare slot, then checks its CRC and that it matches the station type.
  2. New bootloader: written where the old unit only kept old day data, then read back.
  3. Boot sector: the new boot stub is written. From now on the new bootloader starts the unit.
  4. Clearing: the old bootloader area becomes the error log, update journal and swap area, and the record log is cleared.
  5. A "pending update" entry is written to the journal.

E. Finish

  1. The LCD asks to REMOVE JP1+JP2; once both are off, the unit restarts.
  2. The new bootloader installs the production firmware by the normal update path (swap, trial run, confirmed), the same as any SD-card update.

Safety

  • Power cut at almost any point: the unit comes back by itself and the conversion carries on from where it stopped.
  • Running it twice is safe: a converted CTRL chip is left alone, and stored records are kept.
  • Two unsafe moments of under 0.1 s each: rewriting the CTRL chip's first sector and the main chip's boot sector. A power cut at exactly those moments needs the programming jig.
  • The jumpers are only fitted while converting: the converter does not finish until they are removed.

Proven so far

Old unit 2114 (KSNDMC TRG, old firmware TRG5-1.0.5) was converted end to end on 11 Nov 2026 and checked afterwards with a debug probe:

  • Both chips match the production and factory images exactly.
  • The new firmware passed its trial run and is confirmed.
  • The station ID was kept, and the unit is storing records.
  • Afterwards it took a normal firmware update from the menu (v6.9.31) and a normal CTRL update (ctrl.hex, CTRL v1.10), both from the SD card exactly like a new unit.
  • It sends to the server every slot. Its station ID was then changed from the keypad to 1902 without trouble.

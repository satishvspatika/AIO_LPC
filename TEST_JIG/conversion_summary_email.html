Converting old AIO units to the new system with an SD card and two jumpers

Status as of 12 Nov 2026: converter MIG-1.4. The conversion is proven end to end on old unit 2114 (KSNDMC TRG); MIG-1.4 runs on a unit for the first time at the demo.

What it achieves

An old field unit (old main-chip bootloader V1.1, old CTRL firmware) ends up exactly like a new factory unit, in about 2 to 3 minutes. No MCU-Link, no cable, nothing to solder. One SD card converts KSNDMC TRG, BIHAR TRG and KSNDMC TWS units one after another. From then on the unit updates itself from its SD card like any new unit.

Part Before After Backup on the card
CTRL chip Old CTRL firmware, no bootloader CTRL bootloader + CTRL v1.10, the rest blank: identical to a factory flash OLD845.BIN (whole old CTRL firmware)
Main chip Old jump loader, old SD bootloader, old application, day data New boot stub + new bootloader + production firmware v6.9.31, installed and confirmed through the normal update path OLDFLASH.BIN (old bootloader, settings, day data; the old application is erased by the old bootloader itself)
Settings Station ID, old server name and login, other old settings Station ID only. The new firmware has its server and settings built in per type, so the old login is cleared OLDFLASH.BIN

What fw.hex is

fw.hex is a one-time conversion program (about 52 KB), not the station firmware. It is named fw.hex because that is the one file the old unit's own SD bootloader loads, so the old unit starts it by itself. It never sends data to a server.

Inside fw.hex Goes to
The converter programRuns on the main chip in place of the old application
CTRL bootloader (2200 B)CTRL chip
CTRL firmware v1.10 (20184 B)CTRL chip. One build serves all three station types
CTRL rescue sector and loader helperCTRL chip, keeps it recoverable while it is written

Not inside: the production firmware, because it differs per station type. The converter reads it from the card (fw_ksn_trg.hex, fw_bihar.hex or fw_ksn_tws.hex) and checks it is built for that type.

ctrl.hex is not used by the conversion. It is the same CTRL v1.10, packed as a file for normal CTRL updates from MENU > FIRMWARE UPDATE on units already converted.

What you need

  • One microSD card, formatted FAT32 (32 GB or less, not exFAT), holding only:
    • fw.hex: the converter, the same for every unit
    • fw_ksn_trg.hex, fw_bihar.hex, fw_ksn_tws.hex: the v6.9.31 production firmware, all three so any unit converts
    • ctrl.hex (optional): for later CTRL updates
  • Two jumper caps for JP1 and JP2 on the CTRL board

The same card goes from unit to unit. The old bootloader deletes fw.hex after loading it, so the converter writes it back to the card itself.

Field steps

1.Unit off. Fit JP1 + JP2. Insert the card.
2.Power on. Wait about 2 to 3 minutes, watching the LCD.
3.Only if the LCD shows TYPE NOT KNOWN: press UP until the right type shows, then EN, then EN again.
4.When the LCD says REMOVE JP1+JP2, remove both caps. The unit restarts on the production firmware.
5.Take the conversion card out and put the unit's own card in, before the first slot (otherwise the unit writes its logs to the conversion card).
6.If the LCD showed DEFAULT ID USED, set the station ID from the keypad.
7.The clock may be wrong until the first successful send (the next slot), then corrects itself. Until then a firmware update from the menu is refused with SLOT DUE SOON.
8.Back at the office, copy the card's MIGRATE folder to a laptop, then clear it: it holds each unit's old firmware and old server login.

What happens inside, in order

A. The old system loads the converter (blank LCD)

  1. At power-up the old CTRL switches the main chip on (and keeps it on for up to 32 minutes).
  2. The old SD bootloader finds fw.hex, erases the old application, writes the converter in its place, deletes fw.hex and starts it.

B. Checks and backups. Nothing is written to either chip yet

LCD What it does
CONVERTING UNIT / MIG-1.4Checks its own CRC (a damaged copy stops with COPY fw.hex AGAIN). Makes this unit's folder MIGRATE/<station ID>/ (units sharing an ID get <ID>_2, ...)
SD CARD / PUTTING fw.hexWrites fw.hex back from its own flash, byte for byte as built, via a temporary file that is read back before it is renamed, so a power cut never leaves a half-written fw.hex
SD CARD / SAVING OLD FLASHSaves the old main-chip flash to OLDFLASH.BIN
(no screen; TYPE NOT KNOWN only if needed)Reads the station type from the old settings (both old layouts, TRG and TWS, are known). If neither matches, asks on the LCD and saves the choice in the unit's folder
(no screen)Checks the production file for the type is on the card (else NO FIRMWARE FILE) and both jumpers are fitted (else FIT JP1 + JP2)

C. Stage M1: the CTRL chip (LCD: CTRL CHIP ...)

  1. Through JP1/JP2 the main chip resets the CTRL chip into its built-in ROM loader. That loader is part of the chip, so the old CTRL firmware's version does not matter.
  2. Within about 22 ms it loads a 52-byte program into the CTRL chip's RAM, which switches the power back on and keeps it on. (On old units the power board cuts the main chip about 58 ms after the CTRL chip stops driving the power lines.)
  3. It reads the whole CTRL chip and saves the old CTRL firmware to OLD845.BIN. If it already has the new CTRL, nothing is written.
  4. It writes a rescue program to the CTRL chip's first sector first, so a power cut from here still powers the unit up and the conversion carries on.
  5. It writes the CTRL bootloader and v1.10 (both carried inside fw.hex) and reads every sector back.
  6. It writes the real first sector last, then reads the whole chip back and compares.

D. Stage M2: the main chip (LCD: MAIN CHIP ...)

  1. Staging: loads the production firmware from the card into the spare slot, then checks its CRC and that it matches the station type.
  2. New bootloader: written where the old unit only kept old day data, then read back.
  3. Boot sector: the new boot stub is written. From now on the new bootloader starts the unit.
  4. Clearing: the old bootloader area becomes the error log, update journal and swap area; the record log is cleared; the settings are rewritten to the station ID alone (old server login removed).
  5. A "pending update" entry is written to the journal.

E. Finish

  1. The LCD asks to REMOVE JP1+JP2; once both are off, the unit restarts.
  2. The new bootloader installs the production firmware by the normal update path (swap, trial run, confirmed), the same as any SD-card update.
  3. From then on the unit never reads fw.hex. The update menu reads only the per-type files and ctrl.hex, and the new bootloader does not read the card.

Safety

  • Every stop before CTRL CHIP changes nothing: fix what the LCD says and power on again.
  • Power cut at almost any later point: power on again with the jumpers fitted; the conversion carries on from where it stopped.
  • Running it twice is safe: a converted CTRL chip is left alone, and stored records are kept.
  • Two unsafe moments of under 0.1 s each: rewriting the CTRL chip's first sector and the main chip's boot sector. A power cut at exactly those moments needs the programming jig.
  • The jumpers are only fitted while converting: the converter does not finish until they are removed.

Proven so far

Old unit 2114 (KSNDMC TRG, old firmware TRG5-1.0.5) was converted end to end on 11 Nov 2026 and checked afterwards with a debug probe:

  • Both chips match the production and factory images exactly.
  • The new firmware passed its trial run and is confirmed.
  • The station ID was kept, and the unit is storing records.
  • Afterwards it took a normal firmware update from the menu (v6.9.31) and a normal CTRL update (ctrl.hex, CTRL v1.10), both from the SD card exactly like a new unit.
  • It sends to the server every slot. Its station ID was then changed from the keypad to 1902 without trouble.

MIG-1.4 (12 Nov 2026) adds the TWS settings layout and the type menu, keeps fw.hex on the card, gives units with shared IDs their own folders, and clears the old settings. It is built and checked on the bench, and runs on a unit for the first time at the demo.
